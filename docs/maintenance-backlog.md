# Maintenance Backlog

This backlog records small, realistic improvements for future releases.

## v0.2.0 Candidates

### Add Project-Type Checklist Presets

Add beginner-friendly checklist presets for common repository types:

- Static website or small web app
- CLI tool
- Documentation project
- Learning project

Why it helps:

Different projects need slightly different readiness signals. Presets can keep the tool simple while making suggestions more relevant for first-time maintainers.

### Improve Markdown Report Formatting

Make the generated Markdown report more useful when pasted into README files, project notes, or GitHub issues.

Ideas:

- Add a short summary sentence based on the score
- Group missing items by priority
- Include a small next-step checklist

Why it helps:

The report should be something a maintainer can act on immediately, not just a score dump.

### Add a Beginner Guide for GitHub Pages

Add a short guide that explains how a beginner can publish a static project demo with GitHub Pages.

Why it helps:

Many first-time maintainers do not know how to turn a repository into a live demo. A small guide would make OSS Ready Check more practical and easier to learn from.

## Maintenance Principles

- Keep v0.2.0 small enough to finish
- Prefer practical improvements over large rewrites
- Use issues to track public maintenance work once issue write access is available
- Keep the project useful for beginners, not just technically impressive
